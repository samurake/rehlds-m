# ReHLDS-M 1.4.0

Stable launcher-only release for Linux i386 and Windows x86. This is the
cumulative changelog for RC1, RC2 and the subsequent startup/output work.
The existing 32-bit engine, game DLL, Metamod and AMXX interfaces are retained;
this release does not replace those components or parallelize their game loop.

## Included from RC1

- Absolute-deadline pacing accounts for engine work and skips expired
  deadlines without unbounded catch-up bursts.
- Bounded console input, reserved quit capacity, cancellable completion and
  explicit shutdown ordering keep input independent of the engine thread.
- Fix closed-stdin CPU spin, partial-escape shutdown hangs, completion
  cancellation and literal-brace output crashes; preserve bounded formatting.
- Add frame-time reporting through `-framestats` and `rehldsm_stats`.
- Keep console logging available when optional file logging fails.
- Add standalone `--version` with source revision; retain the console editor,
  command history, completion and existing launcher utility options.
- C++20 builds, pinned dependencies, regression/sanitizer checks and verified
  Linux/Windows packaging. Stable dependency versions are listed below.

## Included from RC2

- Remove RC1's accidental GLIBC_2.35 dependency. Enforce a **GLIBC_2.34**
  symbol ceiling on the Linux launcher and every bundled C++ runtime.
- Bundle compatible `libstdc++.so.6` and `libgcc_s.so.1`; leave glibc and
  `/lib/ld-linux.so.2` to the host OS. Preserve the SSE4.2 CPU requirement.
- Run extracted-package regressions and an unwind probe on frozen glibc 2.34
  without the 2.35 backport before publication.
- Provide `check-host.sh`, dependency manifests, provenance, licenses and
  archive/content SHA-256 checksums.
- Bundle the required x86 Visual C++ Release runtime beside `hlds.exe`;
  Windows supplies the Universal CRT and system DLLs.

## Added since RC2

- Startup-only, executable-adjacent `rehldsm.cfg` for pacing, reports and output.
  Strict parsing rejects unknown/duplicate keys, malformed/oversized files
  and out-of-range values before loading the engine.
- Target pacing is **cfg-only**: remove `-targetfps` from launch options.
  All target and pingboost 0–5 modes share a fixed 2000-iteration/s ceiling.
- `--check-config` validates settings without starting the engine. Startup
  reports effective values and their sources; map changes do not reload them.
- Bounded async output moves sink formatting and console/file I/O off the engine
  thread, reserves warning/error capacity, contains failed destinations and
  bounds shutdown. Accepted messages retain order; saturated queues still drop
  messages and report counters. Output is best-effort, not archival storage.
- Percentile calculation/reporting runs on a worker using owned snapshots.
  Lifetime 1/5/10/50 ms iteration-stall counters survive the rolling window
  and map reloads; output/input/report counters expose dropped or failed work.
- `rehldsm_version` reports the loaded version/revision through console and RCON;
  `rehldsm_stats` remains a launcher-input command, not an RCON command.
- GCC 15/Ninja portable Linux release builder, GCC 11 fallback and ASan/UBSan
  lanes, MSVC x86 checks and recorded compiler/dependency/patch provenance.
- Pinned fmt 12.2.0 with its i386 long-double patch, spdlog 1.17.0,
  StringPy 1.0.2 and test-only GoogleTest 1.18.0; portable builds keep native
  CPU targeting off and worker exception support on.
- Separate queue consumption from destination I/O, split metrics regressions
  and document ownership, shutdown and metrics scopes.
- Release packages exclude tests, instrumentation, fixtures, generated graphs,
  engines and plugins. Windows packaging follows only required CRT imports.
  CI also validates documentation and release/instrumentation helpers.

## Startup settings and migration

Install `rehldsm.cfg` beside `hlds_linux` or `hlds.exe`, preserving customized
values. The shipped sample selects 1500; the test profile below selects 2000.

```ini
target_fps = 2000
frame_stats_seconds = 60
async_output = true
output_queue_capacity = 1024
output_flush_ms = 100
```

| Key | Allowed values | Missing-key default | Shipped sample |
| --- | --- | --- | --- |
| `target_fps` | 0–2000 iterations/s | 0 | 1500 |
| `frame_stats_seconds` | 0–3600 seconds | 0 | 60 |
| `async_output` | `true` / `false` | false | true |
| `output_queue_capacity` | 64–4096 slots | 1024 | 1024 |
| `output_flush_ms` | 10–1000 ms | 100 | 100 |

Every setting loads **only at process startup**. Remove `-targetfps` from the
hosting panel; its presence now fails startup with a migration message.
For target pacing, set `sys_ticrate 0` and `fps_max 0` in the game's
`server.cfg`. `target_fps = 0` selects capped pingboost. Explicit
`frame_stats_seconds` overrides `-framestats`; 0 disables automatic reports.
See the [configuration reference](../startup-configuration.md) for precedence,
output bounds and report scopes.

Commands: `--version` and `--check-config` work without the engine;
`rehldsm_version` works in the running server console/RCON, for example
`rcon rehldsm_version`. Request statistics through launcher input with
`rehldsm_stats`.

## Qualification and measured performance

Pre-tag source qualification passed 144 tests in each Linux compiler/sanitizer
lane, 137 Windows tests and 145 frozen-glibc checks per Linux archive.
At cfg target 2000, three fresh-process measurements per population yielded
median accepted engine FPS of **1990.7 at 10 players** and **1913.4 at 32**.
A separate 32-player soak passed 30 measured minutes, four reloads, fourteen
command bursts, 123 engine-response heartbeats and 396 resource samples,
with clean shutdown and no detected crashes, output failures or OOM events.

The [README comparison](../../README.md#measured-performance) also shows the
earlier matched classic/RC2/cfg-only campaign; the longer final-source runs
are not a new paired comparison. A 2000 pacing target does not guarantee
2000 accepted engine frames. These are isolated scripted-client Linux tests,
not production-host or live Windows-engine qualification, and do not prove
long-term memory stability. See [test coverage](../testing.md) and
[benchmarks](../benchmarks.md) for ranges, artifact identities and limits.

The published downloads are fresh clean-tag CI builds, not the earlier
`-dirty` qualification packages. Exact install paths and rollback procedures
for both platforms follow below in the release page and are also in each
archive's `README.txt`.
